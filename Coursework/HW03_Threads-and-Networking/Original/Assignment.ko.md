객체지향프로그래밍및실습의 3차 과제(HW#3)로, 14주차에 나왔다. 문제는 Q1\~Q5의 다섯 개이며 배점은 Q1 20점, Q2 30점, Q3 30점, Q4 10점, Q5 10점이다. 이 레포지토리에는 Q1과 Q3의 풀이가 있다.

- **제출:** 문제와 결과 스크린샷을 채운 보고서(.docx)와 작성한 Java 코드(.java) 전체를 `HW3_YourID_Yourname.zip`으로 압축하여 정해진 시간까지 Blackboard에 제출한다. 조교가 실행했을 때 Java 코드가 깔끔하게 실행되어야 한다.
- **공통 규칙:** 모든 프로그램에 Javadoc 주석을 달고 표준 명명 규칙을 지켜야 한다. 또한 사용자가 잘못 입력해도 프로그램이 절대 종료되면 안 된다. 지키지 않으면 각각 1점을 감점한다. Java 파일(.java) 하나에는 클래스 하나를 두는 것을 원칙으로 하며, 불필요한 중첩 클래스를 작성해도 1점을 감점한다.
- **부분 점수:** 부분 점수가 있으므로 완전히 해결하지 못하더라도 할 수 있는 만큼 시도한다.
- **ChatGPT:** ChatGPT의 남용을 막기 위해 대부분의 문제에서 문제의 패턴 인식은 개발자의 몫으로 남겼다. 문제 제기, 패턴 인식, 요구사항 분할 능력은 ChatGPT가 아직 인간 개발자를 넘어서지 못하는 부분이다.
- **배포 파일:** Q1과 Q2는 함께 배포된 DNA 서열 파일 `Q1.txt`(199,723,309바이트)를 읽는다. 이 파일은 크기 때문에 이 폴더에 두지 않고, 앞부분 300줄을 [`Q1_Sample.txt`](Q1_Sample.txt)로 두었다.

`Q1.txt`는 머리글 줄 없이 대문자 A, C, G, T, N만으로 이루어진 텍스트 파일이다. 한 줄에 60글자씩 3,274,153줄(마지막 줄은 36글자)이며 모두 196,449,156글자이다. 앞의 223줄은 N뿐이고, 224번째 줄의 31번째 글자부터 A, C, G, T가 나온다. `Q1_Sample.txt`는 이 파일의 1\~300번째 줄을 그대로 옮긴 18,000글자이다.

## Q1. DNA 서열의 5글자 조합 빈도 (20점)

백신 개발에서 가장 기본적이고 중요한 일 가운데 하나는 특정 생물 종의 DNA 서열에 결합할 수 있는 단편 서열을 찾는 것이다. `Q1.txt`에는 검색해야 하는 서열의 일부가 들어 있다. 이를 바탕으로 5글자 조합 XXXXX의 빈도를 구하는 프로그램을 개발하라. DNA 서열이므로 각 X에는 "A", "C", "G", "T"만 고려한다. 즉 아래 예시 그림처럼 AAAAA부터 TTTTT까지 모두 1,024가지 경우가 있다. 아래 예에서 주황색으로 표시한 것처럼 한 번에 한 글자씩 이동하는 슬라이딩 윈도우 알고리즘으로, 모두 $`4^5 = 1024`$가지 DNA 서열의 빈도를 출력하는 프로그램을 개발하라. 최종 결과는 `Q1_output.txt`에 저장하고, 기말고사 답안을 제출할 때 함께 제출하라. 또한 연산에 걸린 경과 시간을 명령 창에 반드시 표시하라. 주어진 파일의 "N"은 무시해도 된다(올바르게 구현했다면 자연스럽게 무시된다).

```text
[Query]
AGAGAGAT
AGAGA
 GAGAG
  AGAGA
   GAGAT

[Outcome]                 -> Q1_output.txt
AAAAA: 0
AAAAC: 0
AAAAG: 0
AAAAT: 0
...
AGAGA: 2
...
GAGAG: 1
GAGAT: 1
...
TTTTT: 0
```

*그림 1. 서열 AGAGAGAT에서 한 글자씩 이동하는 5글자 윈도우와 1,024가지 경우의 출력 형식*

보고서에는 경과 시간이 보이는 결과 스크린샷을 붙인다.

## Q2. 병렬 처리로 연산 속도 높이기 (30점)

`Q1.txt`는 실제 문제 규모의 1/100,000,000,000보다 작은 장난감 예제이다. 따라서 실제로 이 연산을 수행하려면(살아 있는 동안 연산을 끝내려면) 반드시 병렬 처리를 해야 한다. 여러 가지 병렬 처리 방법으로 Q1에서 개발한 프로그램의 연산 속도를 높일 수 있다. 조교의 채점용 컴퓨터가 16코어임을 고려하여 최적의 소프트웨어 Q2를 개발하라. 이 문제는 연산 속도가 빠른 순서로 1등부터 꼴찌까지 차등 채점한다(1등 30점). 보고서에는 직접 측정한 경과 시간이 보이는 결과 스크린샷을 붙인다.

## Q3. 공동 계산 클라이언트-서버 프로그램 (30점)

아래와 같은 클라이언트-서버 프로그램을 개발하라. N명의 사용자가 서버에 접속해 공동으로 계산하는 환경을 만들어라. 서버 쪽의 누적 합계 변수를 int형이라고 가정하고, overflow를 일으키는 사용자가 생기면 모든 사용자에게 누가 원인인지 알리고 접속을 종료하라. 아래 화면에서 볼 수 있듯 예외 처리, 멀티스레드 지원, 서버 측의 쿼리 시간 표시와 안내 조건을 반드시 포함하라.

예시 그림에서는 사용자 1, 2, 3, ..., N이 서버 하나에 접속한다. 사용자 1의 화면은 다음과 같다.

```text
#### Welcome to the Real-time calculator ####
Enter one operator and one real number (e.g. +10)
User 1) /0
You can't divided by zero, please try it again!
User 1) +10
The server successfully accepted your query. No overflow occurred.
User 1) *10
The server successfully accepted your query. No overflow occurred.
```

사용자 N의 화면은 다음과 같다.

```text
#### Welcome to the Real-time calculator ####
Enter one operator and one real number (e.g. +10)
User N) -100
The server successfully accepted your query. No overflow occurred.
User N) *100000
The server successfully accepted your query. No overflow occurred.
User N) *100000000000
**User N** caused an overflow on this server.
```

서버의 화면은 다음과 같다.

```text
[Server UI]
Current value is 0. 2024/06/19 16:20:48

[User 1] entered a value (/0). 2024/06/19 16:20:58
Current value is 0.

[User 1] entered a value (+10). 2024/06/19 16:21:02
Current value is 10.

[User N] entered a value (*100). 2024/06/19 16:22:04
Current value is 1000.

[User 1] entered a value (*10). 2024/06/19 16:23:14
Current value is 10000.

[User N] entered a value (*100000). 2024/06/19 16:24:24
Current value is 1000000000.

[User N] entered a value (*100000000000000). 2024/06/19 16:25:00
Overflow!
```

## Q5. 서버에서 계산하는 계산기 (10점)

다음과 같이 모든 연산을 서버에서 수행하는 간단한 서버-클라이언트 모델 기반의 계산기를 구현하라. 사용자 화면에서 누른 버튼의 입력은 서버로 전달되고, 서버가 계산한 결과가 사용자 화면의 표시창에 돌아온다.

```text
│  4  │  5  │  6  │   -   │
├─────┼─────┼─────┼───────┤
│  1  │  2  │  3  │   *   │
├─────┼─────┼─────┼───────┤
│  0  │ AC  │  =  │   /   │
└─────┴─────┴─────┴───────┘
```
